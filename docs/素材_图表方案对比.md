二、四档方案（按"要不要引库"分）

第一档：纯 CSS，零 JS
  background: conic-gradient(#4a7 0 75%, #c96 75% 100%);
  border-radius: 50%;
  优点：两行 CSS，零依赖，服务端吐出来就有图
  缺点：不能做环形（要叠一层圆挖空）、无交互、扇形边界硬切

第二档：手画 SVG（本项目采用）
  <circle pathLength="100" stroke-dasharray="75 100" stroke-dashoffset="0">
  优点：控制权 100%；服务端渲染、无 JS；CSS 可上色/动画
  缺点：起点要自己累加（本文前三个坑）

第三档：零依赖 SVG 小库 —— frappe/charts（15,093 star）
  卖点原话："Simple, responsive, modern SVG Charts with zero dependencies"
  相当于把手画这件事封装好：还是输出 SVG，但不用自己算 dashoffset

第四档：通用图表库（上表）
  适合：多图、tooltip、图例联动、导出图片、大屏


三、针对 Django 模板项目的关键差别

SVG 方案：<circle> 是 Django 模板渲染出来的静态 HTML，浏览器拿到就画，不依赖 JS
JS 库方案：要先引 <script>、等 DOM ready、再把数据塞进 JS 对象

"页面加载完就有图"这件事上，服务端 SVG 是短路路径。
反过来，交互（hover 高亮、tooltip）就全靠自己写。


四、为什么这个项目选手画（三条理由，按重要程度）

1. 在 Django 模板里画图，SVG 是服务端直接输出，不依赖任何 JS 运行时
2. 只有一个图表，为一个环引 6 万 star 的库，收益成本不成比例
3. 想练 SVG（不技术，但真实）

反面：如果要"多图 + tooltip + 图例联动 + 导出图片"，一开始就该上 Chart.js / ECharts。

结论：选型没有标准答案，只有"这一页需要什么"。
