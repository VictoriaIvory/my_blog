我做 Django 投票站时踩的坑：饼图一直是空白的

前几天想给投票结果页加个饼图，看各选项占比。

不想为了一个饼图引 Chart.js 或 ECharts——几十 KB 的库，就为了画个圆环，还要处理加载顺序和配色。于是决定用 SVG 手画。

想法很简单：一个圆环，用 stroke-dasharray 把圆周切成几段，每段的长度就是百分比。

结果第一版出来，整块图是空的——不是画错了，是什么都没有。

后来发现，一共踩了四个坑。


一、不设 pathLength，百分比就没意义

圆的周长是 2πr。想要"这一段占 30%"，就得先算周长，再拿 0.3 去乘。更麻烦的是，r 稍微调一下，所有计算都要跟着改。

后来发现 <circle> 支持一个属性：pathLength="100"。

它的作用是把整条路径的长度重新定义成 100 份，不管实际周长是多少。设了它之后，stroke-dasharray="30 100" 就真的表示"实线 30 份、空白 100 份"，也就是 30%。

半径写成 15.9155 也是同一个道理：2π × 15.9155 ≈ 100，这样配合 pathLength，百分比和半径就对上了，不用记三角函数。


二、多个扇形画在同一个圆上，会互相盖住

我一开始是每个选项画一个完整圆，各自设 dasharray，以为它们会自动拼起来。

实际上每个 <circle> 都是一个完整的圆，后画的会把前面盖掉一部分；而且它们都从同一个起点开始，等于完全重叠。

正确做法是：每个扇形仍然是独立的一个 <circle>，但用 stroke-dashoffset 把它往后推，推到前几个扇形长度之和的位置。

比如第一段 75%，第二段就从 75 的位置开始，dashoffset = -75。

注意是负数。我第一版写成正的，结果两段都从 12 点方向开始，看着像只有一个颜色。


三、SVG 的 0 度在三点钟方向

图是画出来了，但整个饼是躺着的——起点在右边而不是上边。

因为 SVG 的角度从三点钟方向开始，顺时针。加一行 transform: rotate(-90deg) 把整体转 90 度，起点就到正上方了。


四、Django 模板注释不能跨行（这个跟饼图无关，但最坑）

我想在模板里写段注释，解释这段 SVG 在干什么，就顺手写成：

{# 纯 SVG 饼图：pathLength="100" 把圆周归一成 100 份，
   于是 stroke-dasharray 可以直接写百分比 #}

结果页面上直接显示出了这两行文字，而不是被注释掉。

原因是：{# #} 只支持单行。跨行的部分会被当成普通文本输出，而且不报错——页面正常渲染，只是多了一段莫名其妙的字。

正确写法是 {% comment %} ... {% endcomment %}，这个可以跨行。

这个坑最阴的地方在于它不报错。Django 的调试页面什么都不说，你只会看到页面上多了几行字，然后开始怀疑人生。


五、怎么确认它是对的：写测试

饼图这种东西，"看着差不多"是最不可靠的判断。

我把具体数值直接用测试锁死：

def test_results_has_pie_chart_with_correct_segments(self):
    "两段应该是 75% 和 25%，第二段从 75% 处开始"
    ...
    self.assertContains(response, 'stroke-dasharray="75.0 100"')
    self.assertContains(response, 'stroke-dashoffset="-0.0"')
    self.assertContains(response, 'stroke-dasharray="25.0 100"')
    self.assertContains(response, 'stroke-dashoffset="-75.0"')

再加一条防止注释又漏出来：

    self.assertNotContains(response, "这里写的注释")

这样以后不管怎么改样式，只要有一个 dasharray 算错，测试立刻变红。


六、顺便：0 票的时候不要画饼图

还有个体验问题。如果一票都没有，每个扇形长度都是 0，页面上会出现一个全灰的空圆环，看着像加载失败。

所以加了个判断：总票数为 0 时不渲染 svg，而是显示"还没有人投票"。


小结

四个坑里，三个是 SVG 的，一个是 Django 模板的。

但最值得记的不是技术细节，而是这条：

不报错，不等于正确。

多行注释被渲染出来、dashoffset 写成正数、0 票画个空圆——这三个都是"页面能打开、看着有点怪"，不给你任何错误提示。

所以能写测试的地方一定写测试，把数值锁死。它比"我再仔细检查一遍"可靠得多。
