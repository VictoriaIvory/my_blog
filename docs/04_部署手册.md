# 部署手册（PythonAnywhere 免费方案）

> 目标：把本地能跑的博客变成公网可访问的网址（`https://你的用户名.pythonanywhere.com`）。
> 适用：2026-11 的 PythonAnywhere 免费账户。
> 每一步都写了「为什么」，出问题时按第 9 节排查。

## 1. 注册与建 Web 应用

1. 注册 <https://www.pythonanywhere.com/>，记住**用户名**（后面地址就是它）。
2. 顶部 **Web** → **Add a new web app** → **Manual configuration**（不要选自动生成的 Django 模板）→ 选 **Python 3.12**（列表里没有 3.12 就选最接近的 3.11 / 3.13，Django 5.2 都支持）。

## 2. 拉代码、建虚拟环境

打开 **Consoles → Bash**，依次执行（把 `USERNAME` 换成你的用户名）：

```bash
cd ~
git clone https://github.com/VictoriaIvory/my_blog.git my_blog
cd my_blog
python3.12 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

> 仓库是 Public，所以不用配 SSH 密钥，直接 `git clone` 即可。

## 3. 配置环境变量（`.env`）

```bash
cd ~/my_blog
python -c "import secrets; print(secrets.token_urlsafe(50))"   # 生成密钥，复制输出
cat > .env <<'EOF'
DJANGO_SECRET_KEY="把上一步生成的一长串粘贴在这里"
DJANGO_DEBUG=False
DJANGO_ALLOWED_HOSTS=USERNAME.pythonanywhere.com
DJANGO_HTTPS=True
EOF
chmod 600 .env
```

> 三个开关的含义：
> - `DEBUG=False`：关掉调试页（否则出错时会把源码和配置露给所有人）
> - `DJANGO_HTTPS=True`：自动开启 HTTPS 跳转、安全 Cookie、HSTS，并识别 PythonAnywhere 反向代理的 `X-Forwarded-Proto` 头
> - `ALLOWED_HOSTS`：只接受这个域名，防 Host 头攻击

## 4. 数据库与封面图

仓库里**不包含** `db.sqlite3` 和 `media/`（它们不进 Git），有两种选择：

**A. 想把本地文章搬上去（推荐）**
在本地 Windows 上打包：

```powershell
cd D:\ai宝贝\12_我的博客\myblog
Compress-Archive -Path db.sqlite3, media -DestinationPath 上传包.zip -Force
```

然后在 PythonAnywhere 的 **Files** 页面上传到 `/home/USERNAME/my_blog/`，
回到 Bash 解压：

```bash
cd ~/my_blog
unzip -o 上传包.zip
```

**B. 从空站开始**

```bash
cd ~/my_blog
python manage.py migrate
python manage.py createsuperuser
python manage.py seed_posts      # 可选：造演示分类/标签/文章
```

> 不管哪种，都要在**本地或服务器**执行一次下面的迁移，保证表结构最新：
> `python manage.py migrate`

## 5. 收集静态文件

```bash
cd ~/my_blog
python manage.py collectstatic --noinput
```

> 作用：把 `static/` 和 Pygments 样式复制到 `staticfiles/`，生产环境由 WhiteNoise 从这里取文件。
> `staticfiles/` 不进 Git，每次部署都要重新跑。

## 6. 配置 Web 应用（Web 页）

在 **Web** 页面上逐项填写：

| 项 | 填什么 |
|---|---|
| Source code | `/home/USERNAME/my_blog` |
| Working directory | `/home/USERNAME/my_blog` |
| Virtualenv | `/home/USERNAME/my_blog/venv` |

**WSGI 配置文件**：点 `/var/www/USERNAME_pythonanywhere_com_wsgi.py` 的编辑，整段替换成：

```python
import os
import sys

path = '/home/USERNAME/my_blog'
if path not in sys.path:
    sys.path.insert(0, path)

os.environ['DJANGO_SETTINGS_MODULE'] = 'config.settings'

from django.core.wsgi import get_wsgi_application

application = get_wsgi_application()
```

**Static files / Media files 映射**（滚到 Web 页的 Static files 区域，两个都加）：

| URL | Directory |
|---|---|
| `/static/` | `/home/USERNAME/my_blog/staticfiles` |
| `/media/` | `/home/USERNAME/my_blog/media` |

> `/media/` 这一条最容易漏：漏了的话文章能打开，但封面图全是 404。

填完点上方绿色的 **Reload USERNAME.pythonanywhere.com**。

## 7. 验收清单

在手机上或电脑浏览器逐条检查：

| # | 检查 | 预期 |
|---|---|---|
| 1 | 打开 `https://USERNAME.pythonanywhere.com/` | 首页正常、样式正常 |
| 2 | 打开任意一篇文章 | 正文、代码高亮、目录、封面图都在 |
| 3 | 打开 `/admin/` 并登录 | 后台能用，能新建文章 |
| 4 | 打开 `/feed/` | 返回 RSS XML |
| 5 | 打开 `/sitemap.xml` | 返回 URL 列表 |
| 6 | 打开 `/robots.txt` | 有 `Sitemap:` 一行 |
| 7 | 手机访问同一地址 | 响应式布局正常 |
| 8 | 上传一张封面图 | 列表和详情页都能显示 |

`DEBUG=False` 下如果出错，页面上只有 500 提示，去 **Web 页 → Error log** 看具体 traceback。

## 8. 日常维护

```bash
cd ~/my_blog
git pull                      # 拉最新代码
source venv/bin/activate
pip install -r requirements.txt   # 依赖有变化时
python manage.py migrate
python manage.py collectstatic --noinput
python manage.py backup          # 备份数据库 + 封面图到 backups/时间戳/
```

- **备份**：`backups/` 在服务器磁盘上，建议每周在 Files 页下载一次到本地/网盘。
- **更新文章**：直接进 `/admin/` 写，不用动代码。
- **保持不过期**：每月至少访问/打开一次 Web 应用（免费账户 1 个月无访问会过期）。
- **换域名/加域名**：改 `.env` 的 `DJANGO_ALLOWED_HOSTS`，重载 Web 应用。

## 9. 常见问题排查

| 现象 | 原因 | 解决 |
|---|---|---|
| `DisallowedHost` / 400 | `ALLOWED_HOSTS` 没写当前域名 | 改 `.env` 的 `DJANGO_ALLOWED_HOSTS`，Reload |
| 502 / 500 | WSGI 路径、虚拟环境、依赖装错 | 看 Error log；确认 WSGI 里 `path` 和 `config.settings` 正确 |
| 页面没样式 | 没跑 collectstatic，或 `/static/` 映射没配 | 跑 collectstatic；检查映射目录 `staticfiles` |
| 封面图 404 | `/media/` 映射没配，或没上传 `media/` | 加 `/media/` 映射；上传媒体文件 |
| 一直重定向 / 重定向循环 | 开了 HTTPS 但 Django 不知道原始请求是 https | 确认 `DJANGO_HTTPS=True` 且 `SECURE_PROXY_SSL_HEADER` 已生效（本项目 settings 已配） |
| 提交表单报 CSRF 错误 | 跨域或域名不一致 | 用 `https://USERNAME.pythonanywhere.com` 访问；自定义域名时配 `DJANGO_CSRF_TRUSTED_ORIGINS` |
| 上传图片报权限错误 | `media/` 目录不可写 | 确认目录属主和权限（`ls -l`），必要时 `chmod -R u+w media` |
| 改了代码没生效 | 没 Reload，或改了 WSGI 没重载 | Web 页点 Reload；确认代码在 `Source code` 目录 |

## 10. 回滚

```bash
cd ~/my_blog
git log --oneline -5          # 找到要回到的提交
git checkout -f 提交号        # 临时回到某个版本
# 或用迁移回滚：
python manage.py migrate blog 0002   # 回到上一个迁移（慎用，先备份）
```

> 回滚数据库前**一定先 `python manage.py backup`**。
