## 2. 环境：第一次建 venv 就踩坑

### 踩的坑：venv 建成了 Python 3.14

```powershell
python -m venv .venv
```

建完一看 `--version`，**Python 3.14.9**。

原因：PATH 里的 `python` 已经不是系统的了，而是指向 Miniconda 的 base 环境（3.14.9）。

而 **Django 5.2 官方只支持 Python 3.10–3.13**，3.14 装上去能 import，但属于未测试组合，不敢用。

**解决**：删掉重建，显式用 Windows Store 的 3.12：

```powershell
Remove-Item .venv -Recurse -Force
& 'C:\Users\Victoria\AppData\Local\Microsoft\WindowsApps\python.exe' -m venv .venv
& '.\.venv\Scripts\python.exe' -m pip install "Django==5.2.18" "python-dotenv==1.2.4"
```

**教训写进 README 了**：建 venv 之前先 `python --version`，不是 3.12 就别往下走。

### 最终环境

| 项 | 版本 | 备注 |
|---|---|---|
| Python | 3.12.10 | Windows Store 那个，**不是** conda 的 3.14 |
| Django | 5.2.18 | LTS |
| python-dotenv | 1.2.4 | 读 `.env` |
| 数据库 | SQLite | 零配置，够用 |

## 3. 项目结构：为什么叫 `config` 不叫 `myblog`

`django-admin startproject` 默认会用项目名建一个同名包。如果项目目录叫 `myblog`，就会变成：

```
myblog/
└── myblog/
    └── settings.py
```

**同名嵌套，看路径时永远要多想一层**。所以用了：

```powershell
django-admin startproject config .
```

得到 `config/` 作为配置包，目录里只有一层：

```
myblog/
├── manage.py
├── requirements.txt
├── .env                  ← 不进 Git
├── .env.example          ← 进 Git，当模板
├── .gitignore
├── db.sqlite3            ← 不进 Git
├── config/               ← 项目配置
│   ├── settings.py       106 行
│   ├── urls.py             9 行
│   ├── wsgi.py / asgi.py
├── blog/                 ← 应用
│   ├── models.py          21 行
│   ├── admin.py           12 行
│   ├── views.py           13 行
│   ├── urls.py            12 行
│   ├── tests.py           43 行
│   ├── migrations/0001_initial.py   24 行
│   └── management/commands/seed_posts.py  27 行
├── templates/
│   ├── base.html          29 行
│   └── blog/
│       ├── post_list.html      17 行
│       └── post_detail.html    15 行
├── static/css/style.css  143 行
└── docs/
    ├── 01_饼图踩坑.md
    ├── 素材_图表方案对比.md
    └── 00_建站档案_20261109.md  ← 本文件
```

**"项目"和"应用"的区别**：`config` 只管全局配置和总路由；`blog` 放业务。以后加"相册""留言板"就是再加一个应用，不用动 `config` 的结构。

## 4. 模型：5 个字段和三个决定

```python
class Post(models.Model):
    title = models.CharField('标题', max_length=100)
    body = models.TextField('正文')
    is_published = models.BooleanField('已发布', default=True)
    created_at = models.DateTimeField('创建时间', auto_now_add=True)
    updated_at = models.DateTimeField('更新时间', auto_now=True)

    class Meta:
        ordering = ['-created_at']
```

### 决定 1：不用 slug，URL 里放 pk

博客常见做法是 `/post/django-start/` 这种 slug。**第一版没做**，用的是 `/post/1/`。

原因：slug 要自动从标题生成，**中文标题转 slug 很难看**（要么拼音要么一串编码），而手填 slug 又多一道工序。pk 够用、稳、不折腾。

**以后要改**：加 `slug` 字段 + 在 `save()` 里生成 + 改 URL 正则为 `<slug:slug>`，老链接用 `pk` 做重定向。

### 决定 2：`Meta.ordering` 而不是每次 view 里 order_by

```python
ordering = ['-created_at']
```

**好处**：所有查询默认最新在前，视图里不用再写 `order_by`，少一处能忘的地方。
**代价**：每次查询都带 ORDER BY，数据量大时有开销。博客这个量级无所谓。

### 决定 3：详情页把 `is_published=True` 写进查询条件

```python
def post_detail(request, pk):
    post = get_object_or_404(Post, pk=pk, is_published=True)
```

**不是**先查出来再判断，而是查的时候就带上条件。

**效果**：草稿直接 404，别人改 URL 里的数字也看不到。**不用额外写权限判断，天然防越权**。

这一点有测试守着（见第 7 节）。

### 另外：`@property summary`

```python
@property
def summary(self):
    text = self.body.strip().replace('\n', ' ')
    return text if len(text) <= 80 else text[:80] + '…'
```

列表页只需要摘要，放模型里算，模板里直接 `{{ post.summary }}`。

## 5. 后台：不求好看，求"能写文章"

```python
@admin.register(Post)
class PostAdmin(admin.ModelAdmin):
    list_display = ['title', 'is_published', 'created_at', 'updated_at']
    list_filter = ['is_published', 'created_at']
    search_fields = ['title', 'body']
    date_hierarchy = 'created_at'
    readonly_fields = ['created_at', 'updated_at']
```

| 配置 | 解决什么 |
|---|---|
| `list_display` | 列表页一眼看到状态和时间 |
| `list_filter` | 右侧筛"只看草稿" |
| `search_fields` | 文章多了能搜正文 |
| `date_hierarchy` | 按月份跳 |
| `readonly_fields` | 时间字段别让人手改 |

**为什么第一版不做自己写的编辑页**：后台已经把增删改查、富文本、权限全做好了。前端编辑页是阶段 2 以后的事，现在做等于重复造一遍。

## 6. 视图、路由、模板：13 行写完两个页面

### 视图（`blog/views.py`，13 行）

```python
def post_list(request):
    posts = Post.objects.filter(is_published=True)
    return render(request, 'blog/post_list.html', {'posts': posts})

def post_detail(request, pk):
    post = get_object_or_404(Post, pk=pk, is_published=True)
    return render(request, 'blog/post_detail.html', {'post': post})
```

**用函数视图（FBV）不用类视图（CBV）**：
初学阶段 FBV 直白，每条逻辑看得见。等阶段 2 加搜索分页时如果发现重复代码多，再换 CBV 对比——那时换才有感觉，现在换只是抄模板。

### 路由

```python
# config/urls.py
path('admin/', admin.site.urls),
path('', include('blog.urls')),

# blog/urls.py
app_name = 'blog'
path('', views.post_list, name='list'),
path('post/<int:pk>/', views.post_detail, name='detail'),
```

`app_name = 'blog'` 的意义：模板里写 `{% url 'blog:detail' post.pk %}`，以后再加应用也不冲突。

### 模板

- `base.html`：顶栏（站名 + 首页 + 后台）、`{% block content %}`、页脚
- `post_list.html`：`{% for post in posts %}` + `{% empty %}` 空状态
- `post_detail.html`：`{{ post.body|linebreaks }}` 把换行变成段落

**注意 `|linebreaks`**：因为阶段 1 还没做 Markdown，所以正文里写的是纯文本，靠这个过滤器分段。这也是为什么现在的文章里代码块没有缩进——见第 8 节。

### CSS（143 行，无框架）

变量定义配色，正文 `max-width: 760px`，行距 1.8。

**为什么不用 Bootstrap**：国内 CDN 不稳；200 行 CSS 够用；自己写才真学 CSS。

### 第 2 轮：砍到一篇，换主题

- 三篇是"占位"，读者点进去全是"这是占位文章，等内容写好后替换"
- 第一篇的选题**有问题**：那个"记账本"是工时台账项目，不是自己做的，写出来讲不清

### 第 3 轮：重写结构和语气

初稿的问题：

| 问题 | 改法 |
|---|---|
| 六节等长，每节"现象→原因→正确做法"完全同构 | 按**返工顺序**起小标题："第一版画完什么都没有" / "第二版：一个颜色" / "第三版：躺着" |
| 每节结尾都要升华一句 | 拆掉，改成叙述自己的反应 |
| 没有试错痕迹 | 补「清了三次缓存」「盯着负号看了半分钟」 |
| 开头逻辑断裂（"选中一个库"→"自己画吧"） | 补"点开源码看了看它怎么画的 → 原理就这几行 → 那就自己画" |

标题最后定成 **《我做投票demo时遇到的各种drama问题》**，正文加到 **3036 字**。

**结论**：文章的价值不在"技术点多全"，在"时间线真实"和"踩过的坑讲得出来"。占位文章再好也是假的。

## 9. 启动脚本：PowerShell 的 BOM 坑

写了两个：

| 文件 | 用法 |
|---|---|
| `启动.bat` | 双击（最省事） |
| `启动.ps1` | 右键「使用 PowerShell 运行」 |

两者都用 `%~dp0` / `$PSScriptRoot` 定位目录，**不写死中文路径**。启动前检查 venv、.env、8000 端口，起完 3 秒自动开浏览器。

### 踩的坑：脚本报"表达式或语句中包含意外的标记"

第一次运行直接语法错误。原因：

> **PowerShell 5.1 读 `.ps1` 文件时，没有 BOM 的 UTF-8 会被按 GBK 解码。**
> 中文变乱码后，字节里混出引号，把整个脚本的字符串搞坏了。

**解决**：把 `启动.ps1` 存成 **UTF-8 with BOM**：

```powershell
$c = Get-Content 启动.ps1 -Raw -Encoding UTF8
[System.IO.File]::WriteAllText('启动.ps1', $c, (New-Object System.Text.UTF8Encoding($true)))
```

**以后改这个文件，保存时务必保留 BOM**，否则同样报错。`.bat` 没这问题（内容全 ASCII）。

### 另一个坑：Word 锁文件进了仓库

第一次提交时混进 `docs/~$1_饼图踩坑.md`——**Word 打开 md 时生成的临时锁文件**。

已 `git rm --cached` 移除，并在 `.gitignore` 加了：

```
~\$*
```

## 10. 踩坑清单（汇总）

| # | 现象 | 根源 | 解法 |
|---|---|---|---|
| 1 | venv 是 Python 3.14 | PATH 里 `python` 指向 Miniconda | 用绝对路径指向 Store 的 3.12 |

| 6 | 正文换行不生效 | 模板没加过滤器 | `{{ post.body|linebreaks }}` |
