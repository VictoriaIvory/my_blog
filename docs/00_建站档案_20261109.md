## 2. 环境：第一次建 venv 就踩坑

### 踩的坑：venv 建成了 Python 3.14

```powershell
python -m venv .venv
```

建完一看 `--version`，**Python 3.14.9**。

原因：PATH 里的 `python` 已经不是系统的了，而是指向 Miniconda 的 base 环境（3.14.9）。

而 **Django 5.2 官方只支持 Python 3.10–3.13**，3.14 装上去能 import，但属于未测试组合，不敢用。

**解决**：删掉重建，显式用 Windows Store 的 3.12：

```powershell
Remove-Item .venv -Recurse -Force
& 'C:\Users\Victoria\AppData\Local\Microsoft\WindowsApps\python.exe' -m venv .venv
& '.\.venv\Scripts\python.exe' -m pip install "Django==5.2.18" "python-dotenv==1.2.4"
```

**教训写进 README 了**：建 venv 之前先 `python --version`，不是 3.12 就别往下走。

### 最终环境

| 项 | 版本 | 备注 |
|---|---|---|
| Python | 3.12.10 | Windows Store 那个，**不是** conda 的 3.14 |
| Django | 5.2.18 | LTS |
| python-dotenv | 1.2.4 | 读 `.env` |
| 数据库 | SQLite | 零配置，够用 |

## 3. 项目结构：为什么叫 `config` 不叫 `myblog`

`django-admin startproject` 默认会用项目名建一个同名包。如果项目目录叫 `myblog`，就会变成：

```
myblog/
└── myblog/
    └── settings.py
```

**同名嵌套，看路径时永远要多想一层**。所以用了：

```powershell
django-admin startproject config .
```

得到 `config/` 作为配置包，目录里只有一层：

```
myblog/
├── manage.py
├── requirements.txt
├── .env                  ← 不进 Git
├── .env.example          ← 进 Git，当模板
├── .gitignore
├── db.sqlite3            ← 不进 Git
├── config/               ← 项目配置
│   ├── settings.py       106 行
│   ├── urls.py             9 行
│   ├── wsgi.py / asgi.py
├── blog/                 ← 应用
│   ├── models.py          21 行
│   ├── admin.py           12 行
│   ├── views.py           13 行
│   ├── urls.py            12 行
│   ├── tests.py           43 行
│   ├── migrations/0001_initial.py   24 行
│   └── management/commands/seed_posts.py  27 行
├── templates/
│   ├── base.html          29 行
│   └── blog/
│       ├── post_list.html      17 行
│       └── post_detail.html    15 行
```

**"项目"和"应用"的区别**：`config` 只管全局配置和总路由；`blog` 放业务。以后加"相册""留言板"就是再加一个应用，不用动 `config` 的结构。

## 4. 模型：5 个字段和三个决定

```python
class Post(models.Model):
    title = models.CharField('标题', max_length=100)
    body = models.TextField('正文')
    is_published = models.BooleanField('已发布', default=True)
    created_at = models.DateTimeField('创建时间', auto_now_add=True)
    updated_at = models.DateTimeField('更新时间', auto_now=True)

    class Meta:
        ordering = ['-created_at']
```

### 决定 1：不用 slug，URL 里放 pk

博客常见做法是 `/post/django-start/` 这种 slug。**第一版没做**，用的是 `/post/1/`。

原因：slug 要自动从标题生成，**中文标题转 slug 很难看**（要么拼音要么一串编码），而手填 slug 又多一道工序。pk 够用、稳、不折腾。

**以后要改**：加 `slug` 字段 + 在 `save()` 里生成 + 改 URL 正则为 `<slug:slug>`，老链接用 `pk` 做重定向。

### 决定 2：`Meta.ordering` 而不是每次 view 里 order_by

```python
ordering = ['-created_at']
```

**好处**：所有查询默认最新在前，视图里不用再写 `order_by`，少一处能忘的地方。
**代价**：每次查询都带 ORDER BY，数据量大时有开销。博客这个量级无所谓。

### 决定 3：详情页把 `is_published=True` 写进查询条件

```python
def post_detail(request, pk):
    post = get_object_or_404(Post, pk=pk, is_published=True)
```

**不是**先查出来再判断，而是查的时候就带上条件。

**效果**：草稿直接 404，别人改 URL 里的数字也看不到。**不用额外写权限判断，天然防越权**。

这一点有测试守着（见第 7 节）。

### 另外：`@property summary`

```python
@property
def summary(self):
    text = self.body.strip().replace('\n', ' ')
    return text if len(text) <= 80 else text[:80] + '…'
```

列表页只需要摘要，放模型里算，模板里直接 `{{ post.summary }}`。

## 5. 后台：不求好看，求"能写文章"

```python
@admin.register(Post)
class PostAdmin(admin.ModelAdmin):
    list_display = ['title', 'is_published', 'created_at', 'updated_at']
    list_filter = ['is_published', 'created_at']
    search_fields = ['title', 'body']
    date_hierarchy = 'created_at'
    readonly_fields = ['created_at', 'updated_at']
```

| 配置 | 解决什么 |

## 6. 视图、路由、模板：13 行写完两个页面

### 视图（`blog/views.py`，13 行）

```python
def post_list(request):
    posts = Post.objects.filter(is_published=True)
    return render(request, 'blog/post_list.html', {'posts': posts})

def post_detail(request, pk):
    post = get_object_or_404(Post, pk=pk, is_published=True)
    return render(request, 'blog/post_detail.html', {'post': post})
```

**用函数视图（FBV）不用类视图（CBV）**：
初学阶段 FBV 直白，每条逻辑看得见。等阶段 2 加搜索分页时如果发现重复代码多，再换 CBV 对比——那时换才有感觉，现在换只是抄模板。

### 路由

```python
# config/urls.py
path('admin/', admin.site.urls),
path('', include('blog.urls')),

# blog/urls.py
app_name = 'blog'
path('', views.post_list, name='list'),
path('post/<int:pk>/', views.post_detail, name='detail'),
```

`app_name = 'blog'` 的意义：模板里写 `{% url 'blog:detail' post.pk %}`，以后再加应用也不冲突。

### 模板

- `base.html`：顶栏（站名 + 首页 + 后台）、`{% block content %}`、页脚
- `post_list.html`：`{% for post in posts %}` + `{% empty %}` 空状态
- `post_detail.html`：`{{ post.body|linebreaks }}` 把换行变成段落

**注意 `|linebreaks`**：因为阶段 1 还没做 Markdown，所以正文里写的是纯文本，靠这个过滤器分段。这也是为什么现在的文章里代码块没有缩进——见第 8 节。

### CSS（143 行，无框架）

变量定义配色，正文 `max-width: 760px`，行距 1.8。

**为什么不用 Bootstrap**：国内 CDN 不稳；200 行 CSS 够用；自己写才真学 CSS。

## 9. 启动脚本：PowerShell 的 BOM 坑

写了两个：

| 文件 | 用法 |
|---|---|
| `启动.bat` | 双击（最省事） |
| `启动.ps1` | 右键「使用 PowerShell 运行」 |

两者都用 `%~dp0` / `$PSScriptRoot` 定位目录，**不写死中文路径**。启动前检查 venv、.env、8000 端口，起完 3 秒自动开浏览器。

### 踩的坑：脚本报"表达式或语句中包含意外的标记"

第一次运行直接语法错误。原因：

> **PowerShell 5.1 读 `.ps1` 文件时，没有 BOM 的 UTF-8 会被按 GBK 解码。**
> 中文变乱码后，字节里混出引号，把整个脚本的字符串搞坏了。

**解决**：把 `启动.ps1` 存成 **UTF-8 with BOM**：

```powershell
$c = Get-Content 启动.ps1 -Raw -Encoding UTF8
[System.IO.File]::WriteAllText('启动.ps1', $c, (New-Object System.Text.UTF8Encoding($true)))
```

**以后改这个文件，保存时务必保留 BOM**，否则同样报错。`.bat` 没这问题（内容全 ASCII）。

### 另一个坑：Word 锁文件进了仓库

第一次提交时混进 `docs/~$1_饼图踩坑.md`——**Word 打开 md 时生成的临时锁文件**。

已 `git rm --cached` 移除，并在 `.gitignore` 加了：

```
~$*
```

## 16. 第二阶段：分类 + 搜索 + 分页（2026-11-15）

### 做了什么

| 功能 | 实现 | 用到的知识点 |
|---|---|---|
| 分类 | `Category` 模型 + `Post.category` 外键（可空、`SET_NULL`） | `ForeignKey`、`on_delete`、`related_name`、第二次迁移 |
| 分类筛选 | `/?category=Django`，首页顶部分类导航 | `request.GET`、`filter(category=...)` |
| 搜索 | `/?q=饼图`，标题 + 正文，不区分大小写 | `Q` 对象、`icontains` |
| 分页 | `/?page=2`，每页 5 篇（`PAGE_SIZE` 常量） | `Paginator`、`get_page` |
| 翻页保留筛选 | 视图把 `page` 从参数里摘掉，其余重新编码成 `querystring` | `QueryDict.copy/urlencode` |

三个功能共用一个 `post_list` 视图，路由没动——全走 URL 查询参数，可以叠加
`/?category=Django&q=模板&page=2`。

### 三个决定，及理由

1. **分类不加 slug**：和文章同一个理由（中文转 slug 难看）。分类名直接当查询参数，
   Django 自动 urlencode；代价是分类改名会断旧链接，个人博客可接受。
2. **搜索搜正文**：`icontains` 对 SQLite 就是小写化 LIKE，成本低。只搜标题经常
   「明明记得内容却搜不到」。搜索词为空 / 全空格时等于没搜。
3. **分页用 `get_page` 不用 `page`**：`page()` 遇到非法页码抛异常变 500；
   `get_page()` 自动兜底——非数字给第一页，超出范围给最后一页（`page=0` 也归最后一页，
   这是 Django 的 `validate_number` 行为，测试里写明了）。

### 草稿防护的延伸

阶段 1 的「草稿天然 404」结论在阶段 2 继续成立：所有筛选都建立在
`Post.objects.filter(is_published=True)` 之上，分类、搜索、分页三处都加了测试守着。

## 17. 第三阶段：Markdown 渲染 + 代码高亮（2026-11-16）

### 做了什么

| 功能 | 实现 |
|---|---|
| Markdown 渲染 | `blog/markdown_render.py`：`markdown` 库 + 扩展（fenced_code / codehilite / tables / sane_lists / nl2br） |
| 安全清洗 | `bleach.clean` 白名单（标签 / 属性 / 协议），`strip=True`，清洗后 `mark_safe` 输出 |
| 代码高亮 | Pygments：`HtmlFormatter().get_style_defs('.codehilite')` 生成 `static/css/pygments.css`，`base.html` 引入 |
| 模型 | `Post.body_html` 属性（模板里 `{{ post.body_html|safe }}`）；`Post.summary` 改为渲染后 `strip_tags` 再截 80 字 |
| 样式 | `style.css` 增加 Markdown 正文样式：h2/h3、列表、引用、表格、行内代码、代码块 |
| 顺手补的 | 分页条显示页码（页数多时省略号）、自定义 404 页、GitHub Actions 自动跑测试 |

### 三个决定，及理由

1. **渲染后必须用 bleach 清洗**：`markdown` 默认允许 HTML 原样通过，这是 XSS 的入口。
   渲染函数是唯一出口，在这里兜一次底，比在模板里到处记得转义可靠。
   测试里放了 `<script>` 和 `<img onerror>` 两条，保证以后改渲染器不会悄悄失守。
2. **保留 `nl2br` 扩展**：前两阶段正文是纯文本、靠 `|linebreaks` 保留换行；直接切
   Markdown 会把老文章的单换行当空格吃掉。`nl2br` 让单个换行也变 `<br>`，旧文章
   观感不变，新文章写标准 Markdown 也不受影响。
3. **代码高亮配色表用生成的**：Pygments 只输出 `<span class="k">` 这类 class，颜色
   要写在 CSS 里。手抄几百行不现实，生成一次 `pygments.css`（文件头写了来源和生成
   方式），以后换主题重跑即可。

另外：**摘要必须用渲染后的纯文本**。直接截正文会让粗体记号、代码围栏、链接写法
混进列表页，一眼就露馅。

### 踩坑清单（阶段 3）

| # | 现象 | 根因 | 解法 |
|---|---|---|---|
| 1 | 老文章行距被吃掉、变成一大段 | Markdown 把单个换行当空格 | 加 `nl2br` 扩展 |
| 2 | 列表页摘要里出现粗体记号、代码围栏 | 摘要是截正文原文 | 先渲染再 `strip_tags` |
| 3 | 代码块有结构、没颜色 | Pygments 只给 class，缺配色 CSS | 生成 `pygments.css` 并在 base.html 引入 |
| 4 | 正文写 `<script>` 会原样输出 | Markdown 默认放行内嵌 HTML | `bleach` 白名单清洗 |

## 19. 功能扩展：从"只能写文字"到完整博客（2026-11-16 晚）

### 为什么加

反馈"博客目前只能写文字"。原来的文章只有标题 + 正文两个字段：能读，但没有图片、
没有标签、没有阅读量、没有订阅入口，看起来像"能发文章"的 demo，而不像一个博客。

### 加了什么

| 功能 | 实现 | 用到的 Django 知识 |
|---|---|---|
| 封面图 | `Post.cover`（`ImageField`，`upload_to='covers/%Y/%m/'`），后台可传；列表卡片 300px 高、详情页大图 | `ImageField`、`MEDIA_ROOT`、Pillow |

| 阅读量 | `Post.views`；详情页 `update(views=F('views') + 1)` 后 `refresh_from_db()` | `F` 表达式、`aggregate(Sum)` |
| 相关文章 | 详情页底部：先共同标签、再同分类，最多 3 篇 | 多表 `filter` + `distinct` |

| 关于页 | `/about/`：博客介绍 + 技术栈 + 统计 | 简单视图 |
| RSS | `/feed/`：`django.contrib.syndication` 的 `Feed` 子类 | syndication 框架 |
| 站点地图 | `/sitemap.xml`：手写 XML（不引 `sites` 框架） | `HttpResponse` + `content_type` |

### 踩坑清单（功能扩展）

| # | 现象 | 根因 | 解法 |
|---|---|---|---|
| 1 | RSS 报 `'LatestPostsFeed' object has no attribute 'request'` | Django 5.2 的 `Feed` 不再把 request 挂在实例上 | 重写 `get_feed()` 先存 `request`，再用来拼绝对 URL |

| 3 | 上传的封面在开发环境 404 | `MEDIA` 和 `STATIC` 是两套配置 | `config/urls.py` 在 `DEBUG` 时用 `static()` 送 `MEDIA_ROOT` |

| 5 | 相关文章测试误判 | 页面「上一篇/下一篇」里也出现了那篇文章标题 | 断言改成检查 `context['related_posts']` |
