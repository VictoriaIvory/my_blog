让室友用手机给我的投票 demo 投票：ALLOWED_HOSTS 那点事
2026 年 11 月 16 日
投票系统做出来以后，有个很尴尬的问题：只有我自己投。

自己投的票没有意义——每个选项都是 1 票，饼图永远是一样大的几块，演示的时候看着像假数据。所以我想让同一个 WiFi 下的手机也能投，至少拉两个室友帮忙点几下。

我以为这是改个启动参数的事，结果先后遇到两个问题。

## 一、runserver 0.0.0.0 只是第一步

Django 开发服务器默认只监听 `127.0.0.1`，也就是只有本机能访问。要让同一局域网里的手机连进来，需要改成：

```
python manage.py runserver 0.0.0.0:8000
```

`0.0.0.0` 的意思是"监听本机所有网卡"，不再限定只有本机能连。改完以后，在电脑上查自己的局域网 IP：

```
ipconfig
```

找到"无线局域网适配器 WLAN"下面的 IPv4 地址，比如 `192.168.1.23`。手机连同一个 WiFi，浏览器打开 `http://192.168.1.23:8000/polls/`。

第一次启动时 Windows 会弹防火墙提示，要勾"专用网络"然后允许。这一步如果点了取消，手机就会一直转圈打不开——我第一次就点错了，排查了半天才发现是防火墙。

## 二、能连上，但被拒绝：400

手机能打开页面了，但请求返回 400，页面上写着请求的 Host 不被允许。

这时候我才知道 `ALLOWED_HOSTS` 这个东西。Django 会检查每个请求的 Host 头，只放行白名单里的值。这是防"Host 头攻击"的安全设计——网站靠 Host 头判断自己是谁，如果不校验，攻击者可以伪造 Host 让缓存或邮件链接指向别处。

所以只改 `0.0.0.0` 是不够的：别的设备能连上来，但 Host 不在白名单里，还是会被拒。

最直接的做法是把 IP 写进 `ALLOWED_HOSTS`：

```python
ALLOWED_HOSTS = ['127.0.0.1', 'localhost', '192.168.1.23']
```

但这样每换一次网络（宿舍 WiFi、手机热点、教室）就要改一次，肯定会忘。所以我换了个做法：在 `.env` 里加一个开关 `DJANGO_ALLOW_LAN=True`，打开时让 settings 自动探测本机当前的局域网 IP：

```python
if os.environ.get('DJANGO_ALLOW_LAN', '').strip().lower() in ('1', 'true', 'yes', 'on'):
    import socket

    _sock = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
    _sock.connect(('8.8.8.8', 80))   # UDP 不会真的发包，只是让系统选出"出网的那张网卡"
    _lan_ip = _sock.getsockname()[0]
    _sock.close()
    if _lan_ip not in ALLOWED_HOSTS:
        ALLOWED_HOSTS.append(_lan_ip)
```

用的是连一个外网地址（UDP 不实际发包）的办法，让系统告诉我们"当前出网的那张网卡 IP 是多少"。换网络时自动跟着变，不用手改。完全断网时 `connect` 会抛 `OSError`，捕获忽略就行，本机访问不受影响。

这里我还留了一句注释提醒自己：**生产环境不要开这个开关**，应该把域名显式写死。开发图方便，线上图安全，两回事。

## 三、手机真的投了票

配置好以后，室友用手机打开页面，选了一个选项提交，我这边刷新结果页，票数变了。

那一刻才觉得这个 demo 是"能用"的：饼图里有不同人的选择，总票数不再是 1，领先项也真的能领先。

顺便把结果页补了两处：显示总票数、显示当前领先项；首页每个问题也显示累计票数。测试从 5 个补到 13 个，局域网演示也写进了 README。

## 四、回头想

这件事技术上很小——两个配置项、一段自动取 IP 的代码。但它让我第一次意识到：**"本机能跑"和"别人能用"之间隔着一层网络和安全设计**。

`ALLOWED_HOSTS` 一开始我觉得是个麻烦，明明能连上为什么还拒我。后来想明白它挡的是 Host 头攻击，是必要的一道门。自己开发时觉得多余，是因为我默认"请求都是善意的"——线上不能这么假设。
